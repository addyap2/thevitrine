# The Vitrine

A shop window for the websites and apps Antony and Julien build with AI. Every
project stays in its own GitHub account and Vercel project. This site only
collects and links to them.

Built with [Astro](https://astro.build), with no front-end framework and no
animation library. The motion system is documented in [MOTION.md](MOTION.md).

## Add a project

1. On GitHub, open the repo and click the gear icon next to **About**.
2. Put the live URL in **Website**, and add the topic **`thevitrine`**. You can
   add more topics as tags (for example `learning` or `restaurant`).
3. That's it. The daily sync picks it up, takes a screenshot and redeploys.
   To skip the wait, run **Actions → Sync projects → Run workflow**.

The account must be listed in [`vitrine.config.json`](vitrine.config.json).
Each project keeps a `maker` field in the data, but the site never shows it:
every site is presented as The Vitrine's work, by Antony and Julien together.

## Languages

French lives at `/` and English at `/en/`. Visitors choose through the visible
language switch. Pages never redirect based on browser language or a language
cookie. The old `/fr/` address redirects permanently to `/`.

All interface text lives in [`src/i18n.ts`](src/i18n.ts). Category
labels and project descriptions in `overrides.json` are written as
`{ "en": "...", "fr": "..." }`. When a repo has no override, its GitHub
description is used in both languages, so give every new project a French
description in `overrides.json`.

## Polish a project

[`src/data/overrides.json`](src/data/overrides.json) has three parts:

- **`categories`**: the page's sections, in the order they appear. Each one has
  an `id` and a `label`.
- **`projects`**: settings for a repo, keyed by its name. Give each one a
  `category` (one of the ids above) and an `order` within that section. A
  tagged repo without a category shows under "More" until it gets one. Any of
  these fields replaces what GitHub says: `title`, `description`, `url`,
  `tags`, `maker`. The others are `featured: true` to pin it first in its
  section, `inProgress: true` to show a badge, and `hidden: true` to leave it out.
- **`extra`**: projects that aren't on GitHub. Each one needs `slug`, `title`,
  `url` and `maker`. Once a repo with the same name as an extra's `slug` gets the
  topic, the repo version replaces the extra.

To use your own screenshot, put a 16:10 image at `public/shots/<repo-name>.jpg`.

## Run it locally

```bash
npm install
npx playwright install chromium   # once, for screenshots
npm run sync                      # fetch tagged repos → src/data/projects.json
npm run dev
```

`GITHUB_TOKEN` is optional. It raises the rate limit and includes private repos
the token can read. For private repos, the card shows no "Code" link.
`npm run sync -- --all` previews every repo with a website link, whether or not
it has the topic. Don't commit that output.

## How it fits together

- `scripts/sync.mjs` searches GitHub for the topic across the configured
  accounts, applies the overrides, screenshots new sites and writes
  `src/data/projects.json`.
- `.github/workflows/sync.yml` runs that sync every day. If anything changed,
  it commits to `main`, and Vercel redeploys on that push.
- The Astro build reads only the committed JSON, so deploys never depend on the
  GitHub API.
- `npm run build` first runs `scripts/images.mjs`, which makes 480, 800 and
  1280px WebP copies of each screenshot in `public/shots/w/` (not committed).
  Cards and the hero pick the right size for the screen.
- Fonts (Fraunces and Inter) are downloaded at build time and served from this
  site, configured in `astro.config.mjs`.
- `npm run og` renders the share images in `public/og/` from the hero of a
  running preview (`npm run build && npx astro preview`, then
  `npm run og -- http://localhost:4321`). Re-run it when the hero changes.
- Each blog article has its own share image in `public/og/blog/`, made by
  `npm run og:blog` from its title and `cover` project. Re-run it after adding an
  article or changing a title or cover, and commit the images. In an article's
  frontmatter, `cover` picks the screenshot, `cases` the case studies listed at
  the end, and `next` (article keys) the two articles suggested next.
- The site lives at https://thevitrine.fr. In Vercel (Settings → Domains), `www.thevitrine.fr`
  and `thevitrine-eta.vercel.app` redirect to it permanently.
- Security headers and caching live in `vercel.json`; the content security
  policy is generated by Astro (`security.csp` in `astro.config.mjs`).

Before launch, and after big changes, go through [LAUNCH.md](LAUNCH.md).

To include private repos from another account, add a `VITRINE_TOKEN` secret.
It must be a fine-grained token that can read those repos.

## Forms and measurement

Run `npm test` for form regression tests and `npm run build` before publishing.
The two form endpoints require `RESEND_API_KEY`. `FORM_SECRET` is optional;
without it, token signing derives its secret from the email key.

Shared replay protection and rate limits use the connected Upstash Redis
resource through `KV_REST_API_URL` and `KV_REST_API_TOKEN` (the equivalent
`UPSTASH_REDIS_REST_*` names also work). Without these variables, protection
falls back to bounded process memory and is best effort. With Redis configured,
a storage outage rejects the request with a retryable 503 instead of bypassing
protection. Never commit environment files.

Email calls have a 10-second deadline and provider idempotency keys. A request
only succeeds after the team email is accepted. The response includes
`confirmationSent`; the interface explains a failed confirmation without asking
the visitor to resend a request that already reached the team. Acceptance by
the provider does not prove delivery to an inbox; check Resend delivery logs.

Vercel Web Analytics measures page views. `Telemetry.astro` removes URL query
parameters and respects Do Not Track. Conversion events accept only fixed event
names and `fr`/`en`, with no entered text. Daily aggregate counts live in Redis
under `vitrine:events:YYYY-MM-DD` and expire after 90 days. Successful form sends
also emit structured Vercel logs; `confirmation_failed` identifies a failed
acknowledgement. Configure an external alert destination if active notification
is required; logs alone do not notify you.

Published case-study URLs are explicit in `src/data/cases.ts`. Keep an existing
slug when changing a display title. Add an explicit slug for a new case study.
Page modification dates live in `src/data/contentDates.ts`; article `updated`
dates belong in Markdown frontmatter. Update these when content changes, not
when screenshots are refreshed.

See [LAUNCH.md](LAUNCH.md) for checks and remaining owner inputs.
